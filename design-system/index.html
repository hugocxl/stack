@hugocxl/design-system

My signature, across every project I make

  • Version 2.0
  • 18 November 2026

This is how my projects look and read. Large reading type leads every page, line vectors and rounded icons give it an engineered feel, and one orange accent appears at most twice. This page is the complete definition: every token, component and rule a person or an agent needs to build a site with the system is here, and nothing outside it is part of the system.

Read the principles, then color, type, space and layout. Build with the components, icons and vectors and page recipes, check the rules, and brief an agent or install the files.

Principles

  1. 01

    Text leads

    Reading type is 21 px at desktop widths and carries the page. Nothing is set larger than the title.

  2. 02

    Figures explain

    Vectors from @hugocxl/vectors show the subject, and icons from @hugocxl/icons label actions. Neither is ever decoration.

  3. 03

    One accent

    Orange marks at most two things on a page: one phrase in the statement and one status dot. Hues and status colors mark only icons and dots.

  4. 04

    Closed vocabulary

    Pages use the thirteen components below in a recipe’s order. Anything else is a proposal, not part of the system.

  5. 05

    Every rule is checkable

    Each value is a token, and each token is checked in a browser test.

Color

The paper and the orange come from Superlogical. The ink and greys are neutral, with no tint. Muted text is dark enough for supporting copy to meet WCAG AA. Superlogical’s lighter grey survives as faint, for placeholders only.

Use the accent at most twice per page: once as .ds-accent on the last two or three words of the statement, and once as the .ds-dot before a status label. On paper the orange reaches 3:1 only at title size, so it never colors body text, links, buttons, backgrounds or rules.

Hues

Eleven hues color marks: colored icons and status dots, never text or fills. They take after the diffs.com icon palette. The dark values are the reference’s own, with violet and purple lifted for contrast. The light values are deeper versions of the same hues. Each one reaches 3:1 on the canvas and the surface in its theme.

A hue names a kind of thing, the same one everywhere: a language, a tool, a file type or a brand. Grey is not a hue, because an uncolored icon takes the text color. The hues are not the accent and don’t count toward its budget.

Radii are 6px for controls and code, 12px for media and the field, and a full pill for the pager. Every interactive target is at least 44px. Nothing has a shadow.

Layout

Every page uses plain, centered, unless it is a personal home page. Set the layout with data-layout on the body. Text sits in a 30em column, about 65 characters. Wide figures and grids extend to 80rem.

  • Layout / plain
    30em80rem

    Plain

    The default for every page, home included. The column is centered and wide figures are centered on it. The gutter is clamp(1.25rem, 4.5vw, 4rem).

  • Layout / field
    30em80remfield

    Field

    Optional, for a personal home page only, such as hugocxl.me. Never on product, library or docs sites. The column aligns to the left gutter and a fixed textured panel fills the right: clamp(30vw, 100vw − 2 × gutter − 47.6rem, 40vw). At 760px and below it becomes a 12px strip.

Icons and vectors

Pages draw with two companion libraries and nothing else. @hugocxl/icons label actions, and @hugocxl/vectors illustrate ideas. Both draw in the color of the text around them, so they follow the theme and leave the accent alone. No other icon set, illustration, emoji or symbol character may stand in for them.

npm install @hugocxl/design-system @hugocxl/icons @hugocxl/vectors

@hugocxl/icons

Use the Stroke style. An icon either goes before the words of a link, the button or a meta label, or it is the whole content of an icon button with an aria-label. Give the SVG class="ds-icon" and data-icon with its name. It takes the size and color of its text and keeps a small gap before the words.

  • One icon per element. Before words it never replaces a word; alone it needs an aria-label.

Colored icons

An icon takes a color only when the color means something. data-color with a hue marks what an item is, and data-status with a role marks its state. Rules

These hold on every page. A result that breaks one is wrong, whatever else it gets right.

Always

  • Load system/ds.css, system/theme.js in the head and system/ds.js as a module.
  • Set class="ds" and data-layout on the body, as the recipe specifies.
  • Follow the recipe’s component order. Copy component markup exactly and change only text, links, vector and icon names and IDs.
  • Write in sentence case. Keep the title to one line and the statement to one sentence.
  • Use the muted color for supporting sentences, inline after the main thought. Text on the surface is always ink.
  • Keep every vector’s title, give every icon button an aria-label and every field a visible label.
  • Check the page at 320, 760, 761 and 1440px wide in both themes.

Never

  • Never add a class, color, font, size, weight, radius or spacing value that is not a token.
  • Never use the accent more than twice, on body text, links, buttons, backgrounds or rules.
  • Never use a hue or status color on anything but an icon or a dot, or let color alone say what something is or what state it is in.
  • Never set text larger than the title or bolder than 500 (the wordmark is the exception).
  • Never use shadows, gradients, emoji, stock photography, symbol characters as icons, or icons and illustrations from outside @hugocxl/icons and @hugocxl/vectors.
  • Never place two filled buttons on one page.
  • Never center text other than the column itself, and never justify it.
  • Never invent copy, links, numbers, quotes or logos the brief does not supply.

Agent handoff

Give the agent this page and a page plan. Point it at DESIGN.md, which repeats this page in Markdown, at a pinned commit. Write the plan as JSON that validates against plan.schema.json. It names the recipe and lists the blocks in order with their copy.

{
  "designRevision": "<design-system commit SHA>",
  "recipe": "changelog",
  "layout": "plain",
  "blocks": [
    { "component": "masthead", "wordmark": "Fieldwork", "links": [{ "label": "Docs", "href": "/docs" }] },
    { "component": "title", "heading": "Changelog", "byline": "What shipped, newest first" },
    { "component": "index", "items": [
      { "label": "12 Nov 2026", "title": "Persistent sessions", "text": "Sessions survive restarts." }
    ] },
    { "component": "footer", "start": [{ "label": "Press kit", "href": "/press" }], "end": [] }
  ]
}

Make the build repeatable. The same prompt can produce different output, so keep the model’s freedom in the plan, not in the markup. Validate the plan against the schema and check that it follows the recipe. Then render each block by copying its component markup. The same plan and revision always give the same page.

Verify the result. Run the browser tests: computed tokens, column and figure widths, keyboard use, both themes and an axe WCAG 2.2 AA scan. To compare screenshots, fix the browser, viewport, scale, theme, locale and motion settings, and wait for fonts and figures.

Install

Install the package, or copy its system/ folder into the site. Fonts, the field texture and the theme script travel together, with ready-made entries for Tailwind, CSS, Sass and JavaScript. Install @hugocxl/icons and @hugocxl/vectors beside it.

npm install @hugocxl/design-system

Serve the folder with the site and add these lines. With a bundler, import @hugocxl/design-system/ds.css, /theme.js and /ds.js instead.

<link rel="stylesheet" href="system/ds.css">
<script src="system/theme.js"></script>
<script type="module" src="system/ds.js"></script>

Use it in any project. The package also ships the tokens on their own, generated from the stylesheet so they never drift. Pick the entry that fits the project. Every value is a --ds-* custom property, so light and dark keep working.

ProjectImport
Tailwind v4@hugocxl/design-system/tailwind
Tailwind v3@hugocxl/design-system/tailwind-preset and /tokens.css
Plain CSS@hugocxl/design-system/tokens.css and /fonts.css
Sasspkg:@hugocxl/design-system/scss
JavaScript@hugocxl/design-system/tokens or /tokens.json

Tailwind v4 gets the fonts, the tokens and a dark variant tied to the theme, as utilities like bg-canvas, text-ink, text-reading, p-space-5, rounded-media and max-w-measure.

/* app.css */
@import "tailwindcss";
@import "@hugocxl/design-system/tailwind";

Tailwind v3 takes the preset, with the tokens loaded once in the CSS.

// tailwind.config.js
module.exports = {
  presets: [require("@hugocxl/design-system/tailwind-preset")],
};

/* app.css, through your bundler or postcss-import */
@import "@hugocxl/design-system/tokens.css";
@import "@hugocxl/design-system/fonts.css";

Sass maps each token to a variable; load tokens.css once for the values. JavaScript gets the raw values for charts, canvas and native apps.

@use "pkg:@hugocxl/design-system/scss" as ds;
.card { padding: ds.$ds-space-5; color: ds.$ds-ink; }

// JavaScript
import { tokens } from "@hugocxl/design-system/tokens";
tokens.color.dark.canvas; // "#111111"

Before shipping, complete the main task with a keyboard and check reflow at 320px, text zoom at 200%, reduced motion and both themes.
