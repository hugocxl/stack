Design system

A design system for text-led technical websites

  • Version 2.0
  • 18 November 2026

Large reading type leads every page. Line drawings and monospaced labels give it an engineered feel, and one orange accent appears at most twice. This page is the complete definition: every token, component and rule a person or an agent needs to build a site with the system is here, and nothing outside it is part of the system.

Read the principles, then color, type, space and layout. Build with the components, icons and vectors and page recipes, check the rules, and brief an agent or install the files.

Principles

  1. 01

    Text leads

    Reading type is 21 px at desktop widths and carries the page. Nothing is set larger than the title.

  2. 02

    Figures explain

    Hairline drawings and captioned media show the subject. They are never decoration.

  3. 03

    One accent

    Orange marks at most two things on a page: one phrase in the statement and one status dot.

  4. 04

    Closed vocabulary

    Pages use the thirteen components below in a recipe’s order. Anything else is a proposal, not part of the system.

  5. 05

    Every rule is checkable

    Each value is a token, and each token is checked in a browser test.

Color

The paper and the orange come from Superlogical. The ink and greys are neutral, with no tint. Muted text is dark enough for supporting copy to meet WCAG AA. Superlogical’s lighter grey survives as faint, for placeholders only.

Use the accent at most twice per page: once as .p9-accent on the last two or three words of the statement, and once as the .p9-dot before a status label. On paper the orange reaches 3:1 only at title size, so it never colors body text, links, buttons, backgrounds or rules.

Space

Ten steps. Every margin, padding and gap uses one of them. The named roles are the ones you reach for most.

Radii are 6px for controls and code, 12px for media and the field, and a full pill for the pager. Every interactive target is at least 44px. Nothing has a shadow.

Layout

Every page uses one of two layouts, set with data-layout on the body. Text sits in a 30em column, about 65 characters. Wide figures and grids extend to 80rem.

  • Layout / field
    30em80remfield

    Field

    Home and landing pages. The column aligns to the left gutter and a fixed textured panel fills the right: clamp(30vw, 100vw − 2 × gutter − 47.6rem, 40vw). At 760px and below it becomes a 12px strip.

  • Layout / plain
    30em80rem

    Plain

    Articles, docs, changelogs, pricing and contact. The column is centered and wide figures are centered on it. The gutter is clamp(1.25rem, 4.5vw, 4rem).

Thirteen components make up the whole vocabulary. Each one is shown live with its exact markup. Copy the markup, change only the text, links and figure names, and keep every class and attribute.

Icons and vectors

Two companion libraries complete the system. Icons label actions, and Vectors illustrate ideas. Both draw in the color of the text around them, so they follow the theme and leave the accent alone.

npm install @hugocxl/design-system @hugocxl/icons @hugocxl/vectors

Icons

An icon goes before the words of a link, the button or a meta label. Use the Stroke style. It takes the size and color of its text, so it needs no settings of its own.

Read the icon guide

<!-- SVG from @hugocxl/icons, Stroke style -->
<a href="/docs"><svg class="p9-icon" viewBox="0 0 16 16" fill="none" aria-hidden="true">…</svg>Read the guide</a>

// React
import { BookOpenIcon } from '@hugocxl/icons/react/stroke';
<a href="/docs"><BookOpenIcon className="p9-icon" />Read the guide</a>
  • One icon per element, before its words. An icon never replaces a word. Arrows and ◐ stay as text characters.
  • Use icons in links, the button and meta labels only. Keep them out of headings, the statement, body sentences, the masthead and the footer.
  • Hide decorative icons with aria-hidden="true". The React components do this unless you pass an aria-label.
  • Never color an icon with the accent, and never place it on a filled shape.

Vectors

A vector takes the place of a drawing in figure-wide or figure-grid. Inline the SVG with the p9-vector class, and it draws in ink on the surface at its own 4:3 proportions.

<!-- SVG from @hugocxl/vectors: replace the root xmlns with class="p9-vector" and remove its color attribute -->
<figure class="p9-wide">
  <div class="p9-media"><svg class="p9-vector" viewBox="0 0 480 360" role="img" …><title>Modular design</title>…</svg></div>
  <figcaption class="p9-caption"><span class="p9-label">Fig. 02 / Modular design</span></figcaption>
</figure>
  • Choose a vector for what it means. Browse vectors by use case, and name it in the caption.
  • Use one family of figures on a page: vectors or the built-in drawings, not both.
  • Keep the SVG’s title and desc, or give it an aria-label.
  • Never crop a vector, color it with the accent or place it on the field.

Page recipes

A recipe fixes the layout and the order of components. ? means optional, + one or more, * zero or more and | one of. Leave out an optional component when the brief has no content for it.

Rules

These hold on every page. A result that breaks one is wrong, whatever else it gets right.

Always

  • Load system/p9.css, system/theme.js in the head and system/p9.js as a module.
  • Set class="p9" and data-layout on the body, as the recipe specifies.
  • Follow the recipe’s component order. Copy component markup exactly and change only text, links, figure names and IDs.
  • Write in sentence case. Keep the title to one line and the statement to one sentence.
  • Use the muted color for supporting sentences, inline after the main thought. Text on the surface is always ink.
  • Give every figure an aria-label and every field a visible label.
  • Check the page at 320, 760, 761 and 1440px wide in both themes.

Never

  • Never add a class, color, font, size, weight, radius or spacing value that is not a token.
  • Never use the accent more than twice, on body text, links, buttons, backgrounds or rules.
  • Never set text larger than the title or bolder than 500 (the wordmark is the exception).
  • Never use shadows, gradients, emoji, stock photography, or icons and illustrations from outside the stack.
  • Never place two filled buttons on one page.
  • Never center text other than the column itself, and never justify it.
  • Never invent copy, links, numbers, quotes or logos the brief does not supply.

Agent handoff

Give the agent this page and a page plan. Point it at DESIGN.md, which repeats this page in Markdown, at a pinned commit. Write the plan as JSON that validates against plan.schema.json. It names the recipe and lists the blocks in order with their copy.

{
  "designRevision": "<design-system commit SHA>",
  "recipe": "changelog",
  "layout": "plain",
  "blocks": [
    { "component": "masthead", "wordmark": "Fieldwork", "links": [{ "label": "Docs", "href": "/docs" }] },
    { "component": "title", "heading": "Changelog", "byline": "What shipped, newest first" },
    { "component": "index", "items": [
      { "label": "12 Nov 2026", "title": "Persistent sessions", "text": "Sessions survive restarts." }
    ] },
    { "component": "footer", "start": [{ "label": "Press kit", "href": "/press" }], "end": [] }
  ]
}

Make the build repeatable. The same prompt can produce different output, so keep the model’s freedom in the plan, not in the markup. Validate the plan against the schema and check that it follows the recipe. Then render each block by copying its component markup. The same plan and revision always give the same page.

Verify the result. Run the browser tests: computed tokens, column and figure widths, keyboard use, both themes and an axe WCAG 2.2 AA scan. To compare screenshots, fix the browser, viewport, scale, theme, locale and motion settings, and wait for fonts and figures.

Install

Install the package, or copy its system/ folder into the site. Fonts, figures, the field texture and the theme script travel together.

npm install @hugocxl/design-system

Serve the folder with the site and add these lines. With a bundler, import @hugocxl/design-system/p9.css, /theme.js and /p9.js instead.

<link rel="stylesheet" href="system/p9.css">
<script src="system/theme.js"></script>
<script type="module" src="system/p9.js"></script>

Before shipping, complete the main task with a keyboard and check reflow at 320px, text zoom at 200%, reduced motion and both themes.
