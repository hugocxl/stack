CXL Design System

Interface guidelines

Open with one thought a reader can carry down the page. Follow it with a short explanation, then bring in the type, figures, and controls that help someone act on it.

Page structure

Write down what someone came to do. Use that task to choose the page title, the information that follows, and the most prominent action.

Landing page
Give the masthead to the product name. Set one short opening sentence in Geist Serif with generous space above and below. Offer one quiet link underneath. Continue with an introduction and a sequence of titled passages, each with its example close by.
Reading or reference page
Start with the subject and scope. Use descriptive section headings and anchor links for long pages. Keep examples next to the rule they illustrate.
Task or product screen
Put the current object or task in the heading. Group its controls with the content they change. Keep navigation in a consistent location between screens.

Layout and spacing

For editorial pages, align the masthead, opening statement, and prose to one left edge. Keep the text measure near 64ch. Place a specimen in the reading sequence at the point where it answers a question. Reserve multi-column layouts for tasks that require comparison.

Use the six spacing tokens as a starting point. Keep a label 4–8 px from its value, related controls 16 px apart, panel padding around 24 px, and major sections 40–64 px apart. Use a thin rule where two groups still need a visible boundary.

The preview uses an original grayscale texture along the right edge. The field stays still while the text scrolls and narrows to a 12 px strip at 760 px. Keep all information and actions in the reading column. Task screens can use the full width for their controls.

Type and language

Geist Serif
Use for the H1 page title and H2 section headings. Give each page one descriptive H1 and nest subsequent headings by subject.
Geist Sans
Use for body text, navigation, controls, and H3–H6. Start prose at 16 px with roughly 1.5 line height. Aim for 55–70 characters per line in long passages.
Geist Mono
Use for code, commands, identifiers, and technical notes. Apply .cxl-note to a note or .cxl-label to a short technical caption.

Use sentence case. Name the action and its object when the outcome could be unclear. “Save draft” and “Publish page” distinguish two decisions a button labeled “Continue” would hide.

Gray and contrast

Every interface color has equal red, green, and blue values. Use the semantic tokens so the same component works on paper in light mode and near-black in dark mode.

--cxl-bg and --cxl-surface
Use the first for the page and the second for grouped controls, figures, or code samples.
--cxl-text and --cxl-muted
Use the first for primary content and the second for supporting details. Fill the primary button with the text token and use the background token for its label.
--cxl-line
Use for quiet dividers. Give focus, selection, and validation a stronger cue, such as an outline, checkmark, or explicit message.

Follow the system appearance on first visit and remember an explicit choice. Check normal text at 4.5:1 contrast or higher against its actual background in each mode.

Controls and feedback

Use links for destinations and buttons for actions. Use a quiet text or outlined link for an editorial invitation. Give the main submit action in a form the filled .cxl-button treatment. Give secondary actions less emphasis while keeping labels legible.

Give each field a persistent label. Put format hints beside the field. On validation failure, preserve the entry, identify the field, and explain the correction. For example, “Enter a date after 18 November.” Associate the message with the field so assistive technology can announce it.

Group controls on a shared surface

Use one softly rounded surface for persistent navigation or a pair of related actions, such as the figure arrows. The shared .cxl-material style adds a fine inner highlight and a shallow shadow. A translucent fill lets scrolling content show through softly. Keep reading surfaces flat.

Give icon controls a 44 px target and an accessible name. Show a visible focus ring for keyboard use. A brief press movement acknowledges activation. The material becomes opaque with reduced transparency and the press stays still with reduced motion.

Design the states the task can reach

  • Keep keyboard focus visible and distinct from selection. Every pointer action needs a keyboard path.
  • During a save, show “Saving…” and prevent duplicate submissions. Announce completion in place.
  • For an empty list, explain what belongs there and offer the first action. For a failed load, explain what happened and offer a retry.
  • Mark selected items with a persistent cue and expose the corresponding state to assistive technology. Explain unavailable actions when the reason is unclear.

Figures and motion

Choose a bundled Hairline figure when it explains the subject. A keyboard fits a shortcuts guide. Put it beside the shortcut list and keep the commands in selectable text.

Reserve the figure’s space before it loads. Describe meaningful artwork in text and hide purely decorative imagery from assistive technology. Give interactive figures named controls and a usable still view when reduced motion is requested.

Build and review

Copy the system/ directory into the project. Load its stylesheet and theme script in the document head. For the editorial layout, also load system/editorial.css, apply cxl-editorial to the body, and use cxl-masthead, cxl-opening, and cxl-reading for the header, introduction, and prose. A button with id="theme" lets visitors switch appearance.

<link rel="stylesheet" href="system/cxl.css">
<script src="system/theme.js"></script>

<style>
  body {
    background: var(--cxl-bg);
    color: var(--cxl-text);
  }
</style>

Before shipping

  • Read the title, headings, and action labels in order. They should explain the task on their own.
  • Complete the main task with a keyboard. Check focus after opening and closing a dialog and after an error.
  • At a narrow phone width and at 200% zoom, check the longest label, navigation, and form. Keep wide tables or code scrollable within their own region.
  • Try both appearances, reduced motion, and each reachable loading, empty, error, and success state.
