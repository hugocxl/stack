# SF Symbols gap analysis · 18 November 2026

Which SF Symbols concepts @hugocxl/icons should add, so product UIs built with
this library never have to fall back to SF Symbols. SF Symbols is used here as a
coverage checklist only; every addition is drawn as original artwork under the
single-weight contract (1.1 stroke, 1.25 radius).

## Method

1. Read all 9,649 symbol names from the SF Symbols app metadata on macOS.
2. Removed localized variants, Apple device and brand symbols (AirPods, iPhone,
   Apple Watch, Siri, Finder, logos), which are restricted and not ours to draw.
3. Reduced each name to its base concept by stripping modifiers (`.fill`,
   `.circle`, `.square`, `.slash`, `.badge.*`, directions, counts): 1,946 concepts.
4. Matched concepts against our names, tags and known renames (`gearshape` →
   `settings`, `paperplane` → `send`, `doc` → `file`): 542 unmatched, then
   checked by hand to remove false negatives (`robot-vacuum`, `bitcoin`,
   `mouse-pointer-click`, `picture-in-picture` and others already exist).
5. Separately checked the badge and slash variants SF offers on 110 core UI
   families: 190 combinations we lack, most of them `.circle`/`.square`
   containers.

## Not recommended

- Apple devices, logos and services (restricted, trademarked).
- Game-controller shoulder and paddle buttons (`l1`, `r2`, `zl`…), automotive
  warning lamps (`abs`, `4h`, `tsa`…): too specialised for a general library.
- Currency × `bank.building` / `ring` / `gauge.chart` matrices (~100 icons) and
  blanket `.circle` / `.square` containers on every object (~70): combinatorial
  variants with little standalone meaning. Add individually on request.
